## Architecture: provider seam

Each feature gets a protocol in BEMBELKit, a sample implementation, and an
`@Observable` view model in `App/`:

- Domain models move out of `App/Features/Shared/SampleData.swift` into
  `BEMBELKit/Sources/BEMBELKit/Domain/`.
- Protocols: `DeparturesProviding`, `FountainProviding`, `RadarProviding`,
  `CityStatusProviding` — in the kit, so widgets and tests reach them.
- `Sample…Provider` implementations live in the kit (single source for app,
  widgets, previews). Fixture values stay quarantined there.
- Real logic moves to the kit **with tests**: `FountainSeason`, `SunModel`.
- `App/` gets one `@Observable` view model per feature; views render state
  only. Dependencies flow through a single `AppDependencies` value in the
  SwiftUI environment.

Backend lane replaces `Sample…Provider`s with live implementations behind
the same protocols (epics C–G); frontend lane owns views and never blocks.

## Epic S — side quests (post-1.0, milestone M4)

Inspired by Mert Bulan's Franzbrötchen (Hamburg): quizzes, iMessage
stickers, curated discovery, long-tail open data. v1.0 stays locked at five
features; these are the horizon:

- **BEM-S01 Sticker-Sammelalbum** — visit hotspots (Museumsuferfest,
  Kleinmarkthalle, Eiserner Steg, Goetheturm, Lohrberg, Römer, …) →
  unlock salt-glaze/cobalt stickers. On-device geofence detection, progress
  in the App Group store, Game Center achievements mirrored on top.
  Seasonal limited drops (Dippemess, Wäldchestag, Weihnachtsmarkt).
- **BEM-S02 iMessage sticker pack** — unlocked stickers export as an
  iMessage extension.
- **BEM-S03 GrünGürtel roter Faden** — guided walks: GrünGürtel routes +
  Komische-Kunst sculptures as curated discovery threads.
- **BEM-S04 Wasserhäuschen-Register** — kiosk culture as signature dataset;
  consumes bembel-data (see below). In-app UI is the **v1.1 flagship**.
- **BEM-S05 Ebbelwei-Wirtschaften** — traditional Apfelwein taverns.
- **BEM-S06 Baumkataster** — Frankfurt open city-tree register; ties into
  the shade story.
- **BEM-S07 Stolpersteine** — memorial layer with biographies. Explicitly
  never gamified, never sticker-ized.
- **BEM-S08 Blaulicht-Archiv** — incident layer from police press
  releases incl. individual homicide-site markers (operator decision:
  full layer). Brief bakes in: prefer polizei.hessen.de press sources
  over presseportal.de scraping (ToS), markers link their source release,
  no victim names ever.
- **BEM-S09 Baustellen** — construction sites (open data).
- **BEM-S10 Verkehr & Fernverkehr** — airport transfer times, ICE delays,
  traffic.
- **BEM-S11 bembel-data consumption** — app-side loader for versioned
  community-data bundles.

Quizzes (Stadtteil/Haltestellen) were considered and dropped.

## bembel-data (new public repo — the hero's foundation)

"Yelp inside GitHub": community-maintained Frankfurt datasets, reviews as
pull requests.

- Repo `maurice-jobst/bembel-data`, public from day one, **ODbL** licence
  (operator may veto for CC BY before creation).
- JSON Schemas for Wasserhäuschen/Ebbelwei entries and ratings.
- GitHub issue forms ("Wasserhäuschen melden", "Bewertung abgeben"),
  PR-based additions, CI schema validation.
- Releases are versioned data bundles the app pulls (BEM-S11).
- Seeded with schema + a handful of source-verified famous entries only —
  no fabricated data.
- App-side UI ships v1.1; the repo and community flow start now.
